# 資產選擇矩陣

依專案證據決定產出。核心資產提供導航與持久狀態；只有能改善真實回饋迴路時才建立條件式資產。

## 核心資產

| 路徑 | 目的 | 建立規則 |
| :--- | :--- | :--- |
| `AGENTS.md` | 短小的專案知識地圖、精確命令、工作規則與完成條件 | 一律評估；存在時依確認結果更新或重建 |
| `docs/scripts.md` | 保存專案所有已驗證命令及用途 | 一律評估；不存在時建立，存在時保留有效內容並補齊已驗證命令 |
| `ARCHITECTURE.md` | 記錄目前元件、責任、依賴方向、邊界與可執行約束 | 一律評估；未知架構明確標示，不畫理想架構 |
| `PLANS.md` | 定義何時使用持久計畫、必要章節及生命週期 | 一律評估；沿用專案既有計畫命名時同步調整連結 |
| `docs/exec-plans/active/` | 保存進行中且可由新工作階段接續的計畫 | 沒有現行計畫時只建立最小追蹤檔 |
| `docs/exec-plans/completed/` | 保存完成結果、決策與驗證證據 | 沒有完成計畫時只建立最小追蹤檔 |

專案已有等價且廣泛引用的路徑時，優先讓知識地圖指向既有來源，不另建第二套真相來源。

## 計畫檔名

- 新建立的執行計畫若放在 `docs/exec-plans/active/` 或 `docs/exec-plans/completed/`，檔名使用 `YYYYMMDDHHmmss_<原計畫檔名>.md`。
- `YYYYMMDDHHmmss` 是建立當下執行環境本地時間的 14 位數字；計畫移動時保留原時間戳。
- 不符合格式的既有計畫保留原檔名，不執行未經確認的批次改名。

## `scripts.md` 產出規則

- `docs/scripts.md` 只能包含 Markdown table，欄位固定為 `指令` 與 `用途`；既有檔案格式不符時標為 `rebuild`，保留仍有證據的命令資料並移除無法驗證的列。
- 命令必須逐一追溯到套件設定、工作執行器、CI 或版本控制內文件；不得依技術棧推測。
- 沒有可驗證命令時仍建立只含表頭與分隔列的空表格。

## 統一驗證入口

至少有一個真實且可重複的檢查時，才建立或補強統一入口。選擇順序如下：

1. 已存在且文件化的統一驗證命令。
2. 既有工作執行器中的原生 `verify` 任務。
3. 使用專案既有執行環境建立無額外依賴的薄包裝，依序呼叫已驗證命令。

入口必須保留子命令的失敗狀態。沒有可信檢查時，將「建立第一個決定性檢查」記入 active plan；不得用輸出成功訊息或空命令代替。

## 條件式資產

| 資產 | 納入條件 | 不納入條件 |
| :--- | :--- | :--- |
| 設計文件索引 | 已有多份設計文件，或專案明確需要設計決策來源 | 只有單一小型模組且沒有設計文件 |
| 產品規格索引 | 專案包含可辨識的產品行為與規格文件 | 純函式庫且沒有產品流程 |
| 可靠性文件 | 有服務啟動、背景工作、重試、容量或復原責任 | 沒有可觀察的執行期行為 |
| 安全文件 | 有信任邊界、敏感資料、權限、網路或部署風險 | 只能產生空泛安全清單 |
| 品質文件 | 有明確品質原則、債務門檻或定期維護責任 | 沒有可驗證規則或負責範圍 |
| 架構檢查 | 依賴邊界可由現有工具可靠判斷 | 邊界尚未確認或需新增未獲同意的依賴 |
| CI 驗證 | 專案已有 CI，或使用者明確要求建立 | 無法確認 CI 平台或執行環境 |
| 執行期操作手冊 | 有可驗證的啟動、重現與停止方式 | 命令與必要環境未知 |
| 可觀測性指引 | 專案已有日誌、指標、追蹤或介面檢查能力 | 只會產生沒有查詢入口的名詞清單 |
| 持續清理檢查 | 已有可機械判斷的重複、漂移或過期規則 | 只能以主觀風格偏好判定 |

## 預覽格式

```markdown
| Path | Action | Evidence | Planned content | Validation | Recovery |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ... | create/update/rebuild/skip/blocked | ... | ... | ... | ... |
```

`rebuild` 必須列出保留與替換的內容類型。無法清楚界定時標為 `blocked`，並請使用者決定，不可自行覆寫。
