# 產生、驗證與復原

本參考用於使用者確認預覽之後。只實作已確認的精確路徑與動作。

## 產生原則

### `AGENTS.md`

- 保持短小，作為知識地圖而不是完整手冊。
- 指向架構、計畫、設計、可靠性、安全與品質的實際來源。
- 以 `docs/scripts.md` 作為完整命令清單來源；只在 `AGENTS.md` 保留該文件連結與已驗證的統一驗證命令捷徑。
- 沒有可驗證的統一驗證命令時，移除統一驗證命令行與完成條件中的 `{{CANONICAL_VERIFY_COMMAND}}`，不得保留模板標記或填入假命令。
- 寫明開始工作、失敗修正、審查及完成條件。
- 大型細節移到連結文件，檔案不得超過 32 KiB。

### `docs/scripts.md`

- 檔案只能是 Markdown table，第一列固定為 `| 指令 | 用途 |`，第二列為兩欄分隔列。
- 每個資料列只能有兩欄；命令與用途都必須來自專案設定或版本控制內文件的可驗證證據。
- 收錄專案實際會使用的安裝、開發、測試、靜態檢查、建置、啟動、部署及統一驗證命令；沒有證據的命令不得加入。
- 沒有任何可驗證命令時，保留表頭與分隔列，不填入未知或虛構命令。

### `ARCHITECTURE.md`

- 描述目前系統，不描述尚未存在的目標系統。
- 對每個主要元件記錄責任、允許依賴、禁止依賴與執行邊界。
- 依賴方向必須能追溯到目錄、匯入、設定或測試證據。
- 無法確認的邊界列為未知或待決策，不以常見架構模式補空白。
- 已存在可執行約束時附上精確命令；否則清楚區分文件規則與可執行規則。

### `PLANS.md` 與執行計畫

- 定義需要持久計畫的門檻，例如多階段、跨模組、遷移、陌生領域或可能跨工作階段的任務。
- 每份計畫必須自包含；假設讀者只有目前工作樹與計畫本身。
- 新建立的計畫檔名使用 `YYYYMMDDHHmmss_<原計畫檔名>.md`；時間戳取本地時間，從 `active` 移至 `completed` 時沿用。
- 既有未加時間戳的計畫不批次改名；更新既有計畫時維持原檔名與既有連結。
- 計畫至少涵蓋目的、背景、目前與期望行為、限制、工作順序、進度、發現、決策、具體步驟、驗證、復原及結果。
- 實作期間同步更新進度、發現與決策；完成後記錄結果並移至 completed。

### 可執行資產

- 使用專案既有執行器與風格，不引入新的工具只為統一命令名稱。
- 統一驗證必須在任一子檢查失敗時回傳失敗，並輸出足以定位根因的摘要。
- CI 呼叫同一個本機驗證入口，避免維護兩套規則。
- 架構與清理檢查只強制已確認的不變量，不規定無關實作細節。
- 執行期與可觀測性文件必須提供真實啟動、查詢、隔離及停止方式。

## 重建與復原

重建前：

1. 再次確認目標仍與預覽相同，避免覆寫使用者剛完成的變更。
2. 判斷原檔是否由版本控制追蹤；可追蹤時保留清楚 diff。
3. 非版本控制檔案先保存於已報告的暫存位置，再執行重建。
4. 記錄原本仍正確的命令、路徑、限制與決策，並帶入新內容。

不可使用會清除其他工作樹變更的命令。若重建後驗證失敗，先修正新內容；無法安全修正時只還原本次確認的目標，並回報復原結果。

## 驗證清單

- [ ] 寫入路徑完全符合確認清單。
- [ ] 所有模板標記都已替換或移除。
- [ ] 文件內相對路徑存在，或明確標成尚未建立的核准計畫。
- [ ] 新建立的計畫檔案符合 14 位數字時間戳、底線、原檔名與 `.md` 副檔名格式。
- [ ] `docs/scripts.md` 只包含 `指令`、`用途` 兩欄，且每個命令都有來源證據。
- [ ] 命令可從專案設定追溯，且未使用虛構旗標。
- [ ] 架構敘述與程式碼、設定及測試一致。
- [ ] 統一驗證會傳遞失敗狀態，且沒有空殼成功步驟。
- [ ] 條件式資產符合選擇矩陣的證據門檻。
- [ ] 新增與重建內容保持供應商中立。
- [ ] 專案既有快速檢查與完整驗證均已執行。

## 交付格式

```text
Created:
Updated:
Rebuilt:
Skipped:
Blocked:
Validation commands and results:
Recovery information:
Remaining gaps:
```

只報告實際執行結果。跳過、無法執行或失敗的檢查必須明確列出原因。
