# 產生、驗證與復原

使用者確認預覽後才可使用本參考；只實作已確認的精確路徑與動作。

## 產生原則

### `AGENTS.md`

- 保持短小，作為知識地圖使用。
- 指向 `.neo_harness/` 內架構、計畫、設計、可靠性、安全與品質的實際來源。
- 以 `.neo_harness/docs/scripts.md` 作為完整命令清單來源；`AGENTS.md` 只保留該文件連結與已驗證的統一驗證命令捷徑。
- 沒有可驗證的統一驗證命令時，從 `AGENTS.md` 移除統一驗證命令列，以及完成條件中的 `{{CANONICAL_VERIFY_COMMAND}}`；不得保留模板標記或填入假命令。
- 寫明開始工作、失敗修正、審查及完成條件。
- 將大型細節移至連結文件，檔案不得超過 32 KiB。

### `.neo_harness/docs/scripts.md`

- 檔案只能包含 Markdown table；第一列固定為 `| 指令 | 用途 |`，第二列為兩欄分隔列。
- 每個資料列只能有兩欄；命令與用途都必須可由專案設定或版本控制內文件驗證。
- 收錄專案會使用的安裝、開發、測試、靜態檢查、建置、啟動、部署及統一驗證命令；沒有證據的命令不得加入。
- 沒有可驗證命令時，保留表頭與分隔列，不填入未知或虛構命令。

### `.neo_harness/ARCHITECTURE.md`

- 只描述目前系統；不列入尚未存在的目標系統。
- 記錄每個主要元件的責任、允許依賴、禁止依賴與執行邊界。
- 依賴方向必須能追溯到目錄、匯入、設定或測試證據。
- 無法確認的邊界標為未知或待決策，不以常見架構模式補空白。
- 有可執行約束時附上精確命令；否則區分文件規則與可執行規則。

### `.neo_harness/PLANS.md` 與執行計畫

- 定義需要持久計畫的門檻，例如多階段、跨模組、遷移、陌生領域或可能跨工作階段的任務。
- 每份計畫必須自包含；讀者只需目前工作樹與計畫本身，不得依賴先前對話或未連結的外部資訊。
- 計畫目錄固定為 `.neo_harness/docs/exec-plans/active/` 與 `.neo_harness/docs/exec-plans/completed/`。
- 新建立的計畫檔名使用 `YYYYMMDDHHmmss_<原計畫檔名>.md`；時間戳取本地時間，從 `active` 移至 `completed` 時沿用。
- 既有未加時間戳的計畫不批次改名；更新既有計畫時維持原檔名與既有連結。
- 從舊路徑搬遷既有計畫時保留原檔名與時間戳，不因搬遷而重新命名。
- 計畫至少涵蓋目的、背景、目前與期望行為、限制、工作順序、進度、發現、決策、具體步驟、驗證、復原及結果。
- 實作期間同步更新進度、發現與決策；完成後記錄結果並移至 completed。

### 可執行資產

- 使用專案既有執行器與風格，不為統一命令名稱引入新工具。
- 統一驗證必須在任一子檢查失敗時回傳失敗，並輸出可定位根因的摘要。
- CI 呼叫同一本機驗證入口，避免維護兩套規則。
- 架構與清理檢查只強制已確認的不變量，不限制無關實作細節。
- 執行期與可觀測性文件必須提供真實的啟動、查詢、隔離及停止方式。

## 舊路徑搬遷

搬遷是獨立的 `migrate` 動作，必須在寫入預覽中列出並取得使用者明確確認：

| 舊路徑 | 正式路徑 |
| :--- | :--- |
| `ARCHITECTURE.md` | `.neo_harness/ARCHITECTURE.md` |
| `PLANS.md` | `.neo_harness/PLANS.md` |
| `docs/scripts.md` | `.neo_harness/docs/scripts.md` |
| `docs/exec-plans/` | `.neo_harness/docs/exec-plans/` |

- 先檢查來源、目的地、版本控制狀態與忽略規則，再建立搬遷快照或列出可復原依據。
- 目的地已存在、內容衝突或受忽略規則排除時，標記為 `blocked`；不得覆寫、刪除、建立重複副本或符號連結。
- 確認後更新所有受影響的 Harness 相對連結與索引，驗證目的地內容，再依核准方案處理來源。
- 不屬於 Harness 的文件不因路徑相近而搬遷；不確定歸屬時標記為 `blocked`。

## 重建與復原

重建前：

1. 再次確認目標仍與預覽一致，避免覆寫使用者剛完成的變更。
2. 判斷原檔是否由版本控制追蹤；若有追蹤，保留清楚 diff。
3. 非版本控制檔案先保存於已報告的暫存位置，再執行重建。
4. 記錄仍正確的命令、路徑、限制與決策，並帶入新內容。

不得使用會清除其他工作樹變更的命令。重建後驗證失敗時，先修正新內容；無法安全修正時，只還原本次確認的目標，並回報復原結果。

## 驗證清單

- [ ] 寫入路徑完全符合確認清單。
- [ ] 根目錄只有 `AGENTS.md` 作為 Harness 入口，其餘 Harness 產出均位於 `.neo_harness/`。
- [ ] 若有搬遷，來源、目的地與受影響連結均依確認清單處理，且沒有覆寫、重複副本或符號連結。
- [ ] 所有模板標記都已替換或移除。
- [ ] 文件內相對路徑存在，或明確標為尚未建立的核准計畫。
- [ ] 新建立的計畫檔案符合 14 位數字時間戳、底線、原檔名與 `.md` 副檔名格式。
- [ ] `.neo_harness/docs/scripts.md` 只包含 `指令`、`用途` 兩欄，且每個命令都有來源證據。
- [ ] 命令可追溯至專案設定，且未使用虛構旗標。
- [ ] 架構敘述與程式碼、設定及測試一致。
- [ ] 統一驗證會傳遞失敗狀態，且沒有空殼成功步驟。
- [ ] 條件式資產符合選擇矩陣的證據門檻。
- [ ] 新增與重建內容保持供應商中立。
- [ ] 專案既有快速檢查與完整驗證均已執行。

```text
Updated:

```

只報告實際執行結果。跳過、無法執行或失敗的檢查必須列出明確原因。
