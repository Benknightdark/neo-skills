# 專案評估模型

使用本參考建立可追溯的 Harness 現況，不把檔案存在等同於能力已成立。

## 證據來源

依下列順序採信；若內容互相衝突，必須在預覽中指出：

1. 可執行設定：套件腳本、建置檔、測試設定、靜態檢查規則與 CI 工作流程。
2. 實際程式碼：入口、模組依賴、執行邊界、錯誤處理與觀測介面。
3. 版本控制內文件：專案規範、架構、設計決策、產品規格及操作手冊。
4. 使用者在目前對話明確提供的限制與驗收條件。

外部聊天、未提供的服務設定或僅存在個人記憶的資訊都不能當成已驗證事實。

## 盤點面向

| 面向 | 檢查重點 | 有效證據 |
| :--- | :--- | :--- |
| 專案知識 | 是否有短入口與可搜尋的深入文件 | 文件存在、連結有效、內容與程式一致 |
| 架構 | 元件、責任、依賴方向與邊界 | 模組結構、匯入關係、設定與架構測試 |
| 規劃 | 長任務是否有可持續更新的狀態 | 計畫規範、active/completed 目錄、實際計畫 |
| 驗證 | 是否有單一可信入口及失敗訊號 | 可執行命令、非零失敗狀態、CI 使用同一入口 |
| 執行環境 | 是否能在隔離環境啟動與重現 | 啟動命令、測試資料、容器或工作區設定 |
| 可觀測性 | 是否能讀取執行期證據 | 結構化日誌、指標、追蹤、瀏覽器或網路證據 |
| 約束 | 重要不變量是否可執行 | 相依性檢查、結構測試、綱要或安全掃描 |
| 復原 | 長任務與失敗是否可接續 | 版本控制、持久計畫、冪等步驟與復原說明 |
| 維護 | 是否能發現重複、漂移與過期知識 | 定期檢查、品質門檻、責任歸屬與清理流程 |

## 成熟度

成熟度必須附上路徑或命令證據，不用主觀平均分數代替事實。

| 等級 | 判定條件 |
| :--- | :--- |
| 0 — 僅靠即時指示 | 缺少專案知識入口與可信驗證，主要依靠人工搬運資訊。 |
| 1 — 專案可讀 | 有專案規範、基本架構說明與可執行測試，但資訊或入口仍分散。 |
| 2 — 可自行驗證 | 有統一驗證入口、靜態檢查、測試、建置與 CI 閉環。 |
| 3 — 執行期可讀 | 除程式驗證外，還能啟動系統並取得日誌、介面或其他執行期證據。 |
| 4 — 持久工程閉環 | 有持久計畫、隔離工作區、獨立審查、復原與持續清理機制。 |

使用目前由證據完整支持的最高等級。較高等級只有部分能力時，列為下一階段缺口，不提高等級。

## 盤點輸出

預覽至少包含：

```text
Current level:
Evidence:
Existing assets:
Verified commands:
Conflicts:
Unknowns:
Recommended next level:
```

不要執行會改寫檔案的格式化、產生器或修復命令來取得盤點證據。
