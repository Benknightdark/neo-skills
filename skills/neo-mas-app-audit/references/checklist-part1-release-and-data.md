# 檢測基準明細（一）：4.1.1 發布安全 & 4.1.2 敏感性資料保護

依據：《行動應用 App 基本資安檢測基準 V4.0》（中華民國 113 年 9 月）

---

## 4.1.1. 行動應用程式發布安全

### `4.1.1.1.2` 行動應用程式發布說明
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.1.1、MASVS-PLATFORM-1、MASVS-PRIVACY-1
- **技術要求**：行動應用程式應於發布時說明欲存取之敏感性資料、行動裝置資源及宣告之權限用途
- **檢測基準**：
  - 若已發布：檢查是否於應用程式商店，依實際需要說明欲存取之敏感性資料、行動裝置資源及宣告權限用途。
  - 若尚未發布：檢查調查表內是否有說明預計提供欲存取之敏感性資料、行動裝置資源及宣告權限用途。
- **檢測結果**：
  - `符合要求`：符合檢測基準。
  - `不符合要求`：不符合檢測基準。
  - `不適用`：行動應用程式不公開發布（企業內部使用），則此項不須檢測。
- **備註與審核線索**：須於附錄三自我宣告發布來源；對照 `AndroidManifest.xml` `<uses-permission>`、iOS `Info.plist` `NS*UsageDescription` 權限說明與商店隱私宣告文件是否一致。

### `4.1.1.1.3` 行動應用程式提示資訊
- **檢測分類**：`F`
- **檢測依據**：規範 4.1.1.1
- **技術要求**：行動應用程式應於顯著位置（如官網、應用程式下載頁面等）提示使用者於行動裝置上安裝防護軟體
- **檢測基準**：
  - 若已發布：檢查是否於顯著位置（官網、下載頁面或應用程式內等）提示使用者於行動裝置安裝防護軟體。
  - 若尚未發布：檢查調查表內是否填寫「提醒安裝防護軟體之聲明內容及預計聲明位置」。
- **檢測結果**：
  - `符合要求`：符合檢測基準。
  - `不符合要求`：不符合檢測基準。
  - `不適用`：行動應用程式不公開發布，則此項不須檢測。
- **審核線索**：檢查 App 登入頁／關於頁／安全說明畫面或專案文件、官網連結是否包含安裝行動裝置防護軟體提示。

### `4.1.1.3.1` 行動應用程式問題回報
- **檢測分類**：`L2`、`L3`
- **檢測依據**：規範 4.1.1.3
- **技術要求**：行動應用 App 開發者應提供回報安全性問題之管道
- **檢測基準**：
  - 若已發布：檢查是否於應用程式商店或應用程式內提供聯絡網頁、留言板、電子郵件、電話或其他聯絡方式，並經測試可實際聯絡成功。
  - 若尚未發布：檢查調查表內是否說明預計提供回報安全性問題之管道與聯絡方式，並經測試可實際聯絡成功。
- **檢測結果**：
  - `符合要求`：符合檢測基準。
  - `不符合要求`：不符合檢測基準。
  - `不適用`：行動應用程式不公開發布，則此項不須檢測。
- **審核線索**：檢查 App「問題回報 / 客服聯絡 / 關於我們」UI、設定檔聯絡信箱或連結；實際聯絡成功須標為「待人工確認」除非專案已有公開聯繫機制且經確認。

## 4.1.2. 敏感性資料保護

### 4.1.2.1. 敏感性資料蒐集

#### `4.1.2.1.1` 行動應用程式敏感性資料蒐集聲明
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.1、MASVS-STORAGE-1、MASVS-PRIVACY-3
- **技術要求**：行動應用程式應於蒐集敏感性資料前，取得使用者同意
- **檢測基準**：
  - 若已發布：檢查所有蒐集之敏感性資料，是否於應用程式商店內聲明，且於 App 內聲明及取得使用者同意。
  - 若尚未發布：檢查調查表是否填寫敏感性資料類型（資源、權限）、用途說明、是否儲存於裝置內及是否與其他應用分享，並說明如何取得同意，且在 App 內聲明及取得同意。
  - 若不公開發布：檢查是否於 App 內聲明及取得使用者同意。
- **檢測結果**：
  - `符合要求`：符合檢測基準，或行動應用程式未蒐集敏感性資料。
  - `不符合要求`：不符合檢測基準。
- **審核線索**：檢查啟動流程／首次登入／敏感權限請求前是否呈現隱私權聲明與明確同意按鈕（而非預設勾選或未告知即呼叫定位、相機、通訊錄、裝置識別符如 Android ID/IMEI/IDFA）。

#### `4.1.2.1.2` 行動應用程式提供使用者拒絕敏感性資料蒐集機制
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.1、MASVS-STORAGE-1、MASVS-PRIVACY-4
- **技術要求**：行動應用程式應提供使用者拒絕蒐集敏感性資料之權利
- **檢測基準**：
  - (1) 檢查 App 是否提供使用者拒絕蒐集敏感性資料之功能。
  - (2) 檢查在使用者拒絕蒐集的情況下，App 是否未檢出蒐集敏感性資料。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準，或行動應用程式未檢出蒐集敏感性資料。
  - `不符合要求`：不符合任一檢測基準（備註：若 `4.1.2.1.1` 因未聲明所有敏感性資料而不符合，使用者將無法對未聲明項目行使拒絕權利）。
- **審核線索**：檢查拒絕同意或系統權限拒絕後的程式分支：是否停止存取感測器／位置／廣告 ID／Analytics SDK 追蹤，並允許使用者在設定中撤回或拒絕。

### 4.1.2.2. 敏感性資料利用

#### `4.1.2.2.3` 行動應用程式密碼強度認證機制
- **檢測分類**：`F`
- **檢測依據**：規範 4.1.2.2、NIST SP 800-63B、MASVS-AUTH-2
- **技術要求**：行動應用程式如採用密碼認證，應主動提醒使用者設定較複雜之密碼
- **檢測基準**：
  - (1) 檢查密碼設定頁面是否提醒使用者密碼**至少 8 個字元**（業者得舉證主管機關相關公文或證明並依其規定判定）。
  - (2) 檢查密碼設定頁面是否提醒使用者**避免使用個人相關資料**做為密碼（如身分證字號、帳號、姓名、電子郵件、出生年月日等）。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準。
  - `不符合要求`：不符合任一檢測基準。
  - `不適用`：行動應用程式未採用任何密碼機制。
- **審核線索**：檢查註冊、重設密碼、變更密碼畫面之提示文字（placeholder / helper text / 驗證規則）及前端檢核邏輯。

#### `4.1.2.2.4` 行動應用程式密碼期限認證機制
- **檢測分類**：`F`
- **檢測依據**：規範 4.1.2.2
- **技術要求**：行動應用程式應提醒使用者定期更改密碼
- **檢測基準**：檢查 App 是否提醒使用者定期更改密碼，**至多不超過 90 天**（業者得舉證主管機關相關公文或證明並依其規定判定）。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準。
  - `不符合要求`：不符合檢測基準。
  - `不適用`：行動應用程式未採用任何密碼機制。
- **審核線索**：檢查密碼逾期檢查 API 回應處理、本地／後端密碼到期提醒對話框或提示邏輯（≤ 90 天）。

### 4.1.2.3. 敏感性資料儲存

#### `4.1.2.3.1` 行動應用程式敏感性資料儲存聲明
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-PLATFORM-1、MASVS-STORAGE-1、MASVS-PRIVACY-4
- **技術要求**：行動應用程式應於儲存敏感性資料前，取得使用者同意
- **檢測基準**：同 `4.1.2.1.1` 之三種發布狀態檢查規則（針對「儲存」敏感性資料聲明及取得同意）。
- **檢測結果**：
  - `符合要求`：符合檢測基準，或行動應用程式未儲存敏感性資料。
  - `不符合要求`：不符合檢測基準。

#### `4.1.2.3.2` 行動應用程式提供使用者拒絕敏感性資料儲存機制
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-STORAGE-1、MASVS-PRIVACY-4
- **技術要求**：行動應用程式應提供使用者拒絕儲存敏感性資料之權利
- **檢測基準**：
  - (1) 是否提供使用者拒絕儲存敏感性資料之功能。
  - (2) 使用者拒絕儲存時，App 是否未儲存敏感性資料於行動裝置。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準，或未儲存敏感性資料。
  - `不符合要求`：不符合任一檢測基準，或於 `4.1.2.3.1` 因未聲明欲儲存之所有敏感性資料而不符合。

#### `4.1.2.3.4` 行動應用程式敏感性資料儲存限制（關閉及登出後）
- **檢測分類**：`L1`、`L2`（注意：**L3 適用更嚴格之 `4.1.2.3.5`**）
- **檢測依據**：規範 4.1.2.3、MASVS-STORAGE-2、MASVS-PLATFORM-1
- **技術要求**：行動應用程式應避免在關閉及登出後將敏感性資料儲存於冗餘檔案或日誌檔案中
- **檢測基準**：
  - (1) 關閉及登出後未檢出將敏感性資料儲存於冗餘檔案（含暫存檔、Web/HTTP cache、截圖快取等）。
  - (2) 關閉及登出後未檢出將敏感性資料儲存於日誌檔案。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準，或未檢出儲存敏感性資料。
  - `不符合要求`：不符合任一檢測基準。
- **備註與審核線索**：**受作業系統保護之區域亦不可檢出。** 檢查登出／App 關閉生命週期是否有清除 HTTP cache（`URLCache` / `OkHttp Cache`）、`WebView` cache/cookies、暫存檔與本地 log 檔；檢查是否將個資／Token 寫入暫存檔或檔案 log。

#### `4.1.2.3.5` 行動應用程式冗餘檔案或日誌檔案敏感性資料儲存限制
- **檢測分類**：`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-STORAGE-2
- **技術要求**：行動應用程式應避免將敏感性資料儲存於冗餘檔案或日誌檔案中
- **檢測基準**：
  - (1) 是否未檢出將敏感性資料儲存於冗餘檔案。
  - (2) 是否未檢出將敏感性資料儲存於日誌檔案。
  - (3) 是否將敏感性資料儲存於冗餘檔案或日誌檔案且已用**安全加密函式**保護。
- **檢測結果**：
  - `符合要求`：基準 (1)、(2) 皆符合，**或**符合基準 (3)。
  - `不符合要求`：基準 (1) 或 (2) 不符合 **且** 基準 (3) 不符合。
- **備註**：L3 在運行期間即禁止明文寫入快取／暫存／日誌檔；且自 **2023/12/31 起禁用 Triple DES (3DES/DES3)**。檢查是否關閉 HTTP 回應快取（`Cache-Control: no-store`、`URLCache(memoryCapacity: 0, diskCapacity: 0)` 或禁用 `OkHttp Cache`）、禁用 SQLite/Glide/WebView 敏感快取、避免 log 輸出敏感欄位。

#### `4.1.2.3.6` 行動應用程式敏感性資料儲存保護
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-CRYPTO-1
- **技術要求**：敏感性資料應採用適當且有效之金鑰長度與加密演算法，進行加密處理再儲存
- **檢測基準**：
  - (1) 非冗餘檔案及非日誌檔案內之敏感性資料，是否僅採用**金鑰有效長度為 128 位元（含）以上之 AES**，或使用 **ChaCha20**。
  - (2) 加密函式之金鑰是否僅採用符合 **ANSI X9.17、FIPS 140-3、NIST SP 800-22 及 SP 800-90A (CAVP)** 至少其中一項之安全亂數產生函式。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準，或未儲存敏感性資料。
  - `不符合要求`：不符合任一檢測基準。
- **備註與審核線索**：受作業系統保護之區域亦不可檢出明文或弱加密；禁用 3DES/DES/RC4/ECB 模式與非安全亂數（如 `java.util.Random`、`Math.random()`、`rand()`）；應使用 `SecureRandom` / `SecRandomCopyBytes` / `crypto.getRandomValues` 與 AES-GCM/CBC（含隨機 IV）或 ChaCha20-Poly1305、SQLCipher、EncryptedSharedPreferences 等。

#### `4.1.2.3.7` 行動應用程式敏感性資料儲存控管
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-STORAGE-1
- **技術要求**：敏感性資料應儲存於受作業系統保護之區域，以防止其他應用程式未經授權之存取
- **檢測基準**：檢查 App 是否儲存敏感性資料於其他行動應用程式預設無法存取之區域（如 App 沙盒私有目錄）。
- **檢測結果**：
  - `符合要求`：符合檢測基準，或未檢出儲存敏感性資料。
  - `不符合要求`：不符合檢測基準。
  - `不適用`：若敏感性資料之儲存僅於 `4.1.2.3.4` 檢測結果為不符合則此項不須檢測。
- **審核線索**：檢查 Android 是否誤用 `getExternalStorageDirectory()` / `getExternalFilesDir()` / `MODE_WORLD_READABLE` / `MODE_WORLD_WRITABLE` 或公開 `MediaStore`/`Downloads` 存放敏感資料；檢查 iOS 是否將敏感檔案存於 App Group 共享容器或未受保護之共享目錄。

#### `4.1.2.3.8` 行動應用程式敏感性資料硬碼（Hard-coded）
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-CRYPTO-1
- **技術要求**：敏感性資料應避免出現於行動應用程式之程式碼
- **檢測基準**：檢查程式碼與安裝檔內其他檔案（如 `strings.xml`、`.plist`、`assets/`、`.env`、`BuildConfig`、JS bundle），是否未檢出密碼、身分認證資訊或對稱式加解密演算法之金鑰。
- **檢測結果**：
  - `符合要求`：符合檢測基準。
  - `不符合要求`：不符合檢測基準。
- **備註與審核線索**：對應 CWE-259、CWE-321、CWE-798。掃描硬編碼密鑰（AES/HMAC key/IV）、測試帳號密碼、Basic Auth、Private Key、API Secret/Token、資料庫密碼等。

#### `4.1.2.3.9` 行動應用程式畫面擷取警示
- **檢測分類**：`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-PLATFORM-3
- **技術要求**：行動應用程式於非使用者主動進行的畫面擷取時應主動警示使用者
- **檢測基準**：
  - (1) 若畫面擷取是由 App 自身觸發或其他 App 觸發（而非使用者明確要求）：檢查是否主動警示使用者或遮蔽畫面。
  - (2) 若 App 處於**多工模式下（Multitasking Mode）**自動擷取畫面：檢查是否遮蔽畫面。
- **檢測結果**：
  - `符合要求`：**Android** 須符合基準 **(1) 與 (2)**；**iOS** 須符合基準 **(2)**。
  - `不符合要求`：不符合檢測基準。
- **審核線索**：
  - Android：檢查敏感畫面或 `Activity` 是否設定 `WindowManager.LayoutParams.FLAG_SECURE`（同時防護他程式截圖及多工切換縮圖）。
  - iOS：檢查 `applicationWillResignActive` / `sceneWillResignActive`（或 `UIApplication.willResignActiveNotification`）是否覆蓋模糊／遮罩視圖（`UIVisualEffectView` / Splash overlay），並於 `DidBecomeActive` 移除。

#### `4.1.2.3.10` 行動應用程式應適當使用系統憑證儲存設施儲存敏感性資料
- **檢測分類**：`F`
- **檢測依據**：規範 4.1.2.3、MASVS-STORAGE-1
- **技術要求**：行動應用程式應將個人可識別資訊、使用者憑證及加密金鑰等敏感性資料儲存於系統憑證儲存設施
- **檢測基準**：檢查是否將可儲存於系統憑證儲存設施之敏感性資料儲存於內（如 Android Keystore、iOS Keychain）。
- **檢測結果**：
  - `符合要求`：符合檢測基準，或未檢出儲存敏感性資料。
  - `不符合要求`：不符合檢測基準。
- **備註與審核線索**：考量系統儲存限制（如 Keystore 適合存金鑰、Keychain 適合存憑證/金鑰/Token），檢查是否誤將密碼、Token、金鑰明文或自行以硬編碼金鑰存於 `SharedPreferences` / `UserDefaults` / SQLite 而未使用 Android Keystore / iOS Keychain。

#### `4.1.2.3.11` 行動應用程式應於使用者輸入敏感性資料時將鍵盤的快取機制關閉
- **檢測分類**：`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-STORAGE-2
- **技術要求**：行動應用程式應於使用者輸入敏感性資料時將鍵盤的快取機制關閉
- **檢測基準**：檢查輸入敏感性資料欄位時，是否未自動修正且未帶入可能字串。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準，或未提供字串輸入介面。
  - `不符合要求`：不符合任一檢測基準。
- **審核線索**：
  - Android：敏感欄位（密碼、身分證字號、信用卡號、OTP 等）是否設定 `textPassword` / `numberPassword` / `textNoSuggestions`（`TYPE_TEXT_FLAG_NO_SUGGESTIONS`）或 Compose `autoCorrectEnabled = false` / `KeyboardType.Password`。
  - iOS：敏感欄位是否設定 `isSecureTextEntry = true`（或至少 `autocorrectionType = .no`、`spellCheckingType = .no`），SwiftUI `.autocorrectionDisabled(true)` / `SecureField`。
  - Flutter / RN：`autocorrect: false`、`enableSuggestions: false`（`TextField`）、`autoCorrect={false}`。

#### `4.1.2.3.12` 行動應用程式應避免在 IPC 機制中洩漏敏感性資料
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.3、MASVS-PLATFORM-1

- **檢測結果**：

- **審核線索**：

  - iOS：檢查自訂 URL Scheme / Universal Links / `UIPasteboard` / App Extension 傳遞敏感參數時是否有洩漏風險。

#### `4.1.2.3.13` 行動應用程式中的使用者介面應避免洩漏敏感性資料

#### `4.1.2.3.14` 行動裝置作業系統的備份資料中不應存有行動應用程式的敏感性資料

  - (2) 若無進行檔案備份或設定不允許備份。
- **檢測結果**：
  - `符合要求`：符合任一檢測基準（(1) 或 (2)）。
  - `不符合要求`：不符合所有檢測基準。
- **審核線索**：
  - Android：檢查 `AndroidManifest.xml` 中 `<application android:allowBackup="false" ...>`（Android 12+ 亦須檢查 `android:dataExtractionRules` 與 `android:fullBackupContent` 規則是否明確排除敏感檔案）。
  - iOS：檢查敏感檔案是否標記 `URLResourceKey.isExcludedFromBackupKey = true`，以及 Keychain 項目的 `kSecAttrAccessible*ThisDeviceOnly`（排除 iCloud 備份同步）。

### 4.1.2.4. 資料傳輸安全

#### `4.1.2.4.1` 行動應用程式資料傳輸安全
- **檢測分類**：`L1`、`L2`、`L3`
- **檢測依據**：規範 4.1.2.4、MASVS-STORAGE-2、MASVS-NETWORK-1（並依 MASTG V1.7.0 禁止明文傳輸任何資料）
- **技術要求**：行動應用程式透過網路傳輸資料，應使用適當且有效之金鑰長度與加密演算法進行安全加密
- **檢測基準**：
  - (1) 是否僅採用 **TLS 1.2（含）以上**版本加密協定傳輸資料（**禁止明文 HTTP 及 TLS 1.0/1.1/SSLv3**）。
  - (2) 是否僅採用金鑰有效長度為 **2048 位元（含）以上之 RSA**，或 **224 位元（含）以上之 ECC（Elliptic Curve Cryptography）**。
  - (3) 是否僅採用金鑰有效長度為 **128 位元（含）以上之 AES**，或使用 TLS 1.2 所支援的加密演算法（含 ChaCha20）。
- **檢測結果**：
  - `符合要求`：符合所有檢測基準。
  - `不符合要求`：不符合任一檢測基準。
- **備註與審核線索**：禁用 3DES；禁止程式碼中出現未加密 `http://` API 端點、Android `android:usesCleartextTraffic="true"` 或 `network_security_config.xml` `<domain-config cleartextTrafficPermitted="true">`、iOS `Info.plist` `NSAllowsArbitraryLoads = true` / `NSExceptionAllowsInsecureHTTPLoads = true` / `NSExceptionMinimumTLSVersion` 低於 `TLSv1.2`。
