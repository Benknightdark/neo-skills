# 附錄五（參考項目 REF-1 ～ REF-16）與附錄三（檢測資料調查表）

依據：《行動應用 App 基本資安檢測基準 V4.0》（中華民國 113 年 9 月）

---

## 一、附錄五：行動應用 App 基本資安參考項目（僅供參考，不納入強制檢測）

> 基準第 4 節說明：參考項目因「與品質有關未直接影響安全性」、「檢測時間／複雜度或尚無通用檢測方法導致結果不一致」或「非檢測 App 本身可判定」，故**僅供行動應用 App 開發者參考**，不計入檢測合格與否之強制門檻。

| 參考編號 | 對應基準條號 | 技術要求 | 參考說明與建議（含參考來源） |
| :--- | :--- | :--- | :--- |
| **REF-1** | `4.1.1.1.1` | 行動應用程式應於可信任來源之行動應用程式商店發布 | 建議發布於行動作業系統業者、行動裝置製造業者及行動通信業者提供之商店。（NIST SP 800-163 3.1.6） |
| **REF-2** | `4.1.1.2.1` | 行動應用程式應於可信任來源之行動應用程式商店發布更新 | 建議於行動作業系統業者、裝置製造業者及電信業者提供之商店發布更新。（NIST SP 800-163 3.1.6） |
| **REF-3** | `4.1.1.2.2` | 行動應用程式應提供更新機制 | 當程式碼發現安全性弱點時，應提供由可信任來源伺服器端進行更新之機制。（NIST SP 800-163 3.1.5、MASVS-CODE-2） |
| **REF-4** | `4.1.1.2.3` | 行動應用程式應於安全性更新時主動公告 | 建議於有安全性更新時於可信任行動應用程式商店公告。（NIST SP 800-64 3.4、MASVS-CODE-2） |
| **REF-5** | `4.1.1.3.2` | 行動應用 App 開發者應於適當期間內回覆問題並改善 | 屬品質管理面，建議建立問題回覆與改善機制（SLA）。（NIST SP 800-64 3.1.3.5） |
| **REF-6** | `4.1.2.2.1` | 行動應用程式應於使用敏感性資料前，取得使用者同意 | 建議使用敏感性資料前於 App 或可信任應用商店聲明並取得使用者同意。（NIST SP 800-163 3.1.4） |
| **REF-7** | `4.1.2.2.2` | 行動應用程式應提供使用者拒絕使用敏感性資料之權利 | 建議提供使用者拒絕使用敏感性資料之功能。（NIST SP 800-163 3.1.4） |
| **REF-8** | `4.1.2.3.3` | 行動應用程式儲存之敏感性資料，應僅用於其使用聲明之用途 | 建議僅在聲明範圍內使用敏感性資料。（NIST SP 800-163 3.1.4、MASVS-PLATFORM-1、MASVS-STORAGE-1） |
| **REF-9** | `4.1.2.3.15` | 行動應用程式應避免重複使用相同的對稱式加密金鑰 | 對稱式加密金鑰不應重複使用於多種用途（應依用途分鑰或 Key Derivation）。（MASVS-CRYPTO-2） |
| **REF-10** | `4.1.2.6.1` | 行動應用程式如涉及儲存使用者敏感性資料，應提供使用者刪除之功能 | 建議執行刪除功能後，敏感性資料不以任何形式繼續存在於行動裝置。（NIST SP 800-163 3.1.4） |
| **REF-11** | `4.1.5.2.1` | 行動應用程式應使用適當且有效之完整性驗證機制，以確保其完整性 | 建議 (1) 開發者提供 App 雜湊值（Hash）供驗證完整性；(2) 採用混淆技術保護商業邏輯。（OWASP Checklist V7.2、MASVS-RESILIENCE-2/4） |
| **REF-12** | `4.1.5.5.2` | 行動應用程式應可主動偵測在沙盒中所有檔案以及資料是否有遭到竄改 | 建議實作沙盒檔案與資料防竄改偵測。（MASVS-RESILIENCE-2） |
| **REF-13** | `4.1.5.5.3` | 行動應用程式應偵測行動裝置中是否有使用動態分析工具或框架 | 建議實作 Frida / Xposed / Cycript 等動態分析工具／框架偵測。（MASVS-RESILIENCE-4） |
| **REF-14** | `4.1.5.5.4` | 行動應用程式應偵測在記憶體中的程式碼以及資料是否遭到竄改 | 建議實作執行階段記憶體程式碼與資料防竄改偵測。（MASVS-RESILIENCE-2） |
| **REF-15** | `4.1.5.5.5` | 屬於該行動應用程式的可執行檔案及函式庫應於檔案層級或重要程式碼／資料區段加密或加殼 | 因已強制要求 F 類進行混淆（`4.1.5.5.6`），此項不強制加殼，供進階防逆向參考。（MASVS-RESILIENCE-2） |
| **REF-16** | `4.2.2.1.1` | 行動應用程式應使用 Webview 與遠端伺服器進行網頁資源交換 | 與遠端伺服器進行網頁資源交換時，若跳轉外部 App（如惡意瀏覽器）恐有資料外洩風險，建議優先使用受控管之 Webview。 |

## 二、附錄三：行動應用 App 基本資安檢測資料調查表（自評與送測對照欄位）

> ※ 本表填寫內容均須與應用程式商店公開之資訊一致。送測前或內部資安審核時，應逐一核對以下 22 項資訊是否已備齊：

| 編號 | 項目 | 填寫內容說明／審核對照 |
| :---: | :--- | :--- |
| 1 | 送檢單位名稱 | 開發商或申請送測單位名稱 |
| 2 | 連絡資訊 | 承辦聯絡方式 |
| 3 | 受測行動應用程式通用名稱 | 商店顯示名稱／App 名稱 |
| 4 | 唯一識別名稱 | Android Package Name (`applicationId`) / iOS Bundle ID |
| 5 | App 雜湊值 | `MD5`、`SHA1`、`SHA256`（冒號分隔十六進位格式） |
| 6 | 作業系統 | Android 版本 / iOS 版本 / 其他 |
| 7 | 程式版本 | 送測版本號 |
| 8 | App 類別 | `L1`（無須身分鑑別）/ `L2`（須身分鑑別）/ `L3`（含交易行為）；選填 `+F`（高安全性加測） |
| 9 | 發布狀態 | 內部使用不公開發布 / 已發布 / 尚未發布（預計日期）及發布商店 URL（App Store / Google Play / 其他） |
| 10 | 需要之敏感性資料類型（資源、權限）、用途說明、是否儲存於裝置內以及是否與其他應用分享 | 用於驗證 `4.1.1.1.2`、`4.1.2.1.1`、`4.1.2.3.1` |
| 11 | 提醒安裝防護軟體之聲明內容及預計聲明位置 | 已發布不須填寫；用於 F 類 `4.1.1.1.3` |
| 12 | 分享敏感性資料之預計分享內容、用途說明、如何取得同意及分享之應用程式 | 已發布不須填寫；用於 `4.1.2.5.1` |
| 13 | 隱私權宣告網址 | 公開隱私權政策 URL |
| 14 | 問題回覆與改善機制之具體聯絡方式 | 發布於 App 內 / 商店內；聯絡網頁、電子郵件、電話或其他（用於 `4.1.1.3.1`） |
| 15 | 引用函式庫名稱、版本、來源（含作業系統內建及第三方函式庫） | 格式：`<函式庫名稱 / 版本 / 來源>`（用於 `4.1.5.3.1`） |
| 16 | 連線是否採加密方式（第一類 L1 免填） | 是（加密協定如 TLS 1.2 / 1.3）／否（原因） |
| 17 | 加密演算法所使用之亂數產生函式庫說明 | 格式：`使用 <XX 亂數產生函式庫> 於 <OO 加密演算法>`（用於 `4.1.2.3.6`） |
| 18 | App 是否為免費版 | 是 / 否 |
| 19 | 是否使用 Webview | 是（網域名稱列表）／否（用於 `4.2.2.1.2`） |
| 20 | 封包流向國家宣告 | 國內 / 其他國家名稱列表（用於 `4.1.4.2.4`） |
| 21 | 封包流向網域名稱 | 所有通訊網域名稱列表（用於 `4.1.4.2.4`） |
| 22 | 備註 | 其他補充說明 |
